# 安全评估（v0.4.x）

> 结论先行：**没有发现能让未授权者直接拿到隧道或数据的漏洞**；真正危险的是
> **运维姿势**（把控制面暴露到公网、明文 HTTP、抢注管理员）。本轮把代码里能修的
> 都修了，剩下的属于「部署时必须注意」的清单。

## 0. 威胁模型：谁能打到什么

| 攻击者位置 | 能碰到的东西 | 能不能得手 |
|---|---|---|
| 公网任意人 | 隧道 UDP 端口（28333）、控制面端口（若转发到公网）、`/api/enroll`、`/install.sh`、`/agent-dist/*` | 没有密钥/安装码时：握手被拒；只能做握手洪水的 DoS（已限速） |
| 同局域网的人 | 上面这些 + Windows 防火墙内的 Docker 端口 | 同上；控制面若明文 HTTP，可嗅探到登录口令/动态码 |
| 拿到一台已授权客户端的人 | 自己那份 `.srkey`（内含私钥） | 只能访问自己被 ACL 允许的站点；私钥泄露需换密钥 |
| 拿到站点机器 root 的人 | 站点私钥、本机站点配置 | 可冒充该站点（顶替它接收流量）；换一个安装码即可吊销 |
| 拿到控制面容器/数据目录的人 | server.json（hub 私钥）、clients.json（含所有客户端 TOTP）、数据库 | **全盘沦陷**——这是最需要防的一条 |

## 1. 本轮已修（按危险程度）

| # | 问题 | 危险 | 修法 |
|---|---|---|---|
| 1 | **抢注管理员**：控制面一旦可达，任何人都能在你之前注册第一个账号（= 接管整个系统） | 高 | `init.sh` 生成 `bootstrap-token`；注册页必须填令牌。没有令牌文件时只允许内网/本机来源注册 |
| 2 | **客户端 TOTP 密钥裸奔**：`clients.json`（含每个设备的 TOTP 明文）被写成 0644，同主机其他用户可读 → 配合口令即可冒充 | 高 | 注册表统一 0600（web 写入时显式 chmod） |
| 3 | **登录/注册无来源限速**：只有「按用户名」限速，攻击者可跨账号爆破、刷注册 | 高 | 新增按 IP 限速（30 次/15 分钟），与原有 5 次/5 分钟叠加 |
| 4 | **登录 CSRF**：`POST /login`、`/register` 在拿到会话前就生效，SameSite 帮不上忙（可被强制登录到攻击者账号） | 高 | 全站 POST 增加 Origin/Referer 同源校验（无这两个头的脚本客户端仍可用，保持自动化） |
| 5 | **UDP 握手洪水**：未认证的握手每次都花一次 X25519，可被伪源地址打满 CPU | 中高 | 按来源 IP 令牌桶（突发 30、5/s 补充），超限静默丢弃 + 每分钟一次告警日志 |
| 6 | **管控 API 监听 0.0.0.0**：局域网内可读状态、可踢线（token 很强但走明文） | 中 | `init.sh` 默认改成 `127.0.0.1:8770`（生产栈 server/web 同机，够用）；桌面覆盖文件里仍发布，仅供开发机 |
| 7 | **Host 头注入**：站点页的安装命令用请求 Host 拼出来，伪造 Host 可让管理员复制到攻击者的地址 | 中 | 校验 Host 只允许主机名/IP 字符，非法则隐藏命令并提示 |
| 8 | **没有改密码入口**：口令泄露无法自助轮换 | 中 | 新增「修改密码」（需当前密码 + 完整 MFA 会话），并立即吊销该用户其它会话 |
| 9 | 会话 Cookie 无 `Secure`（HTTPS 部署下浏览器仍会明文发送） | 中 | 新开关 `COOKIE_SECURE=1`（compose `.env`）；上 TLS 后打开 |
| 10 | 空注册表 `.tmp` 权限、缺少响应头 | 低 | 临时文件同样 0600；nginx 加 `X-Content-Type-Options`/`X-Frame-Options`/`Referrer-Policy`/COOP/CSP |
| 11 | 容器未限制提权 | 低 | web/server 加 `security_opt: no-new-privileges:true` |

## 2. 原本就做对了的（复核结论）

- **密码**：argon2id（m=64MB, t=3, p=4）；登录失败文案统一，不泄漏用户名是否存在
- **隧道**：Noise IK 双向认证 + X25519 + ChaCha20-Poly1305 + BLAKE2s；显式 nonce + 64 位滑窗（防重放）；未授权握手静默丢弃；重密钥前的会话不可被旧 nonce 撑爆
- **数据面**：用户态中转逐包校验源地址（防伪造）、目标网段、在线状态与 ACL；站点间/客户端间默认不可互访
- **密钥落盘**：`.srkey` 用 argon2id 派生 + ChaCha20-Poly1305 信封加密（AD 绑定），站点点私钥从不出现在控制面
- **接入码**：8 位（约 40 bit 熵）、60 分钟有效、一次性、可随时轮换；`/api/enroll` 每 IP 20 次/小时
- **CSRF**：所有已登录态的表单都有 token（本轮又补了跨站兜底）
- **文件权限**：`server.json`/`api-token`/`agent-home.json`/`preprovision/*.json` 均 600
- **权限边界**：设备/站点按属主校验，管理操作需 admin；`authMFA` 要求会话已过动态码

## 3. 残余风险（设计取舍，需要你知道）

| 风险 | 为什么留着 | 怎么降低 |
|---|---|---|
| **站点链路没有动态码**（v0.4 按需求降级） | 无人值守的站点维护 TOTP 成本高；改为「安装码 + 密钥对」 | 安装码只在可信通道传递；站点页能立刻看到「已接入」的主机名；怀疑泄露就点「生成新安装码」（旧机器立即失效） |
| **控制面是明文 HTTP** | 脚手架阶段没上 TLS | 只在内网/隧道内访问；要在公网暴露请加反代 + 证书，然后开 `COOKIE_SECURE=1` |
| **安装脚本经 HTTP 下发** | `curl \| bash` 图省事 | 优先在可信网络执行；高安全场景用「离线部署包」人工搬；后续计划给包加签名/校验和 |
| **站点配置里的私钥是明文**（600） | 与 hub 同机同信任域 | `--keypass` 可加密；磁盘加密/权限收紧即可 |
| **控制面容器内是 root** | 群晖上数据卷常归 root，避免权限摩擦 | 已加 no-new-privileges；后续可改非 root + 只读根文件系统 |
| **数据库里的 TOTP/口令哈希** | hub 必须能验动态码 | 备份加密；别把 DB 端口暴露（compose 里未发布） |
| **恢复码是哈希**（✓）但不能自助重新生成 | 绑定流程可重跑 | 换手机时重新走绑定流程即可 |

## 4. 部署清单（务必）

1. **控制面不要直接暴露公网**：只在局域网/隧道内可达；确需公网访问就上 HTTPS 反代，并设 `COOKIE_SECURE=1`
2. **不要暴露管控 API 端口**（8770）：`init.sh` 已默认只监听 127.0.0.1，别改回去
3. 部署完**尽快注册管理员**（令牌机制已挡抢注，但也别拖）
4. 定期检查：`docker compose logs server | grep 握手限速`、`grep unauthorized`（异常握手＝有人在扫）
5. 定期轮换：站点安装码、客户端 `.srkey`；客户端丢了就「吊销」
6. 备份 `data/` 目录（含 hub 私钥与注册表）要加密存放，别进 Git（`.gitignore` 已挡 `.env`）

## 5. 自查命令

```sh
# 注册表权限（应全 600）
ls -l data/clients.json data/agents.json data/server.json data/api-token
# 管控 API 是否只在环回
ss -lntp | grep 8770        # 或 netstat -an | grep 8770
# 隧道握手是否被扫
docker compose logs server | grep -cE "unauthorized|握手限速"
# 谁在连（客户端/站点）
curl -s -H "Authorization: Bearer $(cat data/api-token)" http://127.0.0.1:8770/api/v1/status | jq .totals
```
