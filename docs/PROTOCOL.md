# selfremote 隧道协议规格 v0.1（草案）

> 状态：M1.0 实现目标 · 2026-09-11

## 1. 设计原则

1. **密码学全部来自成熟库**，绝不自创算法；协议"骨架"（消息编排、会话、帧格式）自研
2. UDP 承载，面向 IP 包（L3 隧道）
3. 版本化帧头，为后续演进（中继、封装层）留空间
4. 传输层可插拔：协议核心不感知"包是怎么到对端的"

## 2. 密码套件

**Noise_IK_25519_ChaChaPoly_BLAKE2s**，使用 Go 库 `github.com/flynn/noise` 实现。

- 双方各持一对 X25519 静态密钥（`sr genkey` 生成，base64 存于配置）
- 客户端预置网关公钥（防中间人）；网关持有客户端公钥白名单（未授权握手静默丢弃）
- IK 模式：两轮完成，双向认证 + 前向保密；`Split()` 得到两个方向的 `CipherState`
- 数据加密：ChaCha20-Poly1305（Noise 传输模式），nonce 计数器由会话状态管理

## 3. 帧格式

每个 UDP 数据包通用头：`[ver:1 = 0x01][type:1]`，其后按类型：

| type | 名称 | 载荷 |
|---|---|---|
| `0x01` | HS_INIT | Noise IK 消息 1 |
| `0x02` | HS_RESP | Noise IK 消息 2 |
| `0x03` | DATA | AEAD 密文（明文 = 一个完整 IP 包） |
| `0x04` | KEEPALIVE | AEAD 密文（空明文） |
| `0x05` | CTRL | AEAD 密文（TKLV/JSON），预留：中继协商、端点更新、配置推送 |

开销核算：IPv6 40B + UDP 8B + 帧头 2B + AEAD tag 16B = **66B**；tun MTU 取 `1360` → 线路上限 `1426B` < 1500，无需分片。

## 4. 会话管理

- **握手重传**：客户端 2s 间隔重试，失败后退避到 10s 循环；服务器对每个 init 都回复（幂等）
- **重密钥**：120s 或 2^20（≈104 万）个包，先到者触发；先建新会话、短暂并行收包、再拆旧
- **保活**：空闲 10s 发 KEEPALIVE；25s 未收到任何合法包 → 判定断线 → 重新握手
- **乱序处理（MVP 折衷）**：Noise nonce 严格递增；乱序/解密失败的包直接丢弃（内层 TCP 自动重传，实际影响可忽略）。v0.2 引入「显式 nonce + 64 位滑动窗口」彻底解决
- **重放防护**：nonce 单调性天然防重放（重放旧帧必然解密失败）

## 5. 寻址与路由

- 隧道网段 `10.77.0.0/24`：网关 `10.77.0.1/24`，客户端 `10.77.0.2/32`
- 客户端注入路由：家庭 LAN 网段（如 `192.168.1.0/24`）→ utun
- 网关：`net.ipv4.ip_forward=1` + `POSTROUTING MASQUERADE -s 10.77.0.0/24`
- DNS：MVP 不转发内网 DNS；直接用内网 IP 访问（M3 再议 mDNS / 内网 DNS）

## 6. 配置格式

`gateway.json`：

```json
{
  "listen": "[::]:28333",
  "private_key": "<base64, 32B>",
  "tunnel_cidr": "10.77.0.1/24",
  "peers": [
    { "name": "mac", "public_key": "<base64, 32B>" }
  ]
}
```

`client.json`：

```json
{
  "server": "nas.example.com:28333",
  "private_key": "<base64, 32B>",
  "server_public_key": "<base64, 32B>",
  "tunnel_cidr": "10.77.0.2/32",
  "routes": ["192.168.1.0/24"]
}
```

约定：私钥文件权限 600；配置里绝不出现私钥明文以外的秘密（无预共享口令，认证靠密钥白名单）。

## 7. 未来扩展（已预留的演进点）

- **中继模式**：CTRL 帧做端点重协商；帧结构不变
- **封装层（抗 QoS）**：在 UDP 之下/之外再套 TCP / QUIC 外形，协议核心不变
- **UDP 打洞**：需要会合服务器时，新增 CTRL 消息类型即可
- **多客户端**：网关 `peers` 列表天然支持，需要时加逐客户端路由
- **Windows / Linux 客户端**：同一代码库，交叉编译即可
