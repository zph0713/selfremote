# v0.5.0 — 看得见：站点/客户端两张表 + 活跃端口与实时流量

## 场景

以前控制面只能告诉你「站点在线、累计跑了多少字节」。至于**谁在访问站点的哪个端口、
现在跑多快**，完全看不见——排查「内网服务到底通没通」「是不是有人在拉大文件」「某个
端口怎么突然没流量了」只能去站点机器上抓包。

v0.5.0 把中转服务端看到的东西直接搬到网页上。服务端本来就是用户态中继，每个包都过它手，
所以这件事不需要 agent 配合、不需要抓包、不需要新端口。

## 新增页面

- **客户端连接**（`/clients`）：每台已注册设备的在线状态、隧道地址、可访问站点、
  当前速率、累计流量、最近活跃。点设备名进详情。
- **站点 Agent** 列表新增「当前速率」列；站点详情新增「活跃端口与流量」表格。
- **客户端详情** 同样带「活跃端口与流量」表格。
- 端口表每 2 秒自动刷新（只刷新表格，不整页重载），按「协议 + 站点地址 + 端口」聚合，
  显示两个方向的速率/累计/最近时间。

## 口径与边界（重要）

- 「活跃端口」= **隧道里实际观测到的目的端口**，不是扫描站点主机得到的监听端口。
  服务端从不主动扫描任何站点。
- 端口显示 `—` 表示 ICMP（无端口）或分片（非首片没有传输层头）。
- 数据只存在服务端**内存**里（上限 4096 条流，空闲 2 分钟回收），服务端重启即归零；
  页面标注「自服务端启动以来」。不写数据库，避免高频写拖垮 MariaDB。
- 流表满了会**降级为只计数**（新增流量不再进明细），转发本身不受任何影响。

## 控制 API（给 GUI / 脚本用）

| 端点 | 说明 |
|---|---|
| `GET /api/v1/overview` | 一次拿全：总量 + 所有 peer（含 `rx_bps`/`tx_bps`）+ 流表占用 |
| `GET /api/v1/clients` | 只列客户端 peer |
| `GET /api/v1/peers/{id}/ports?limit=50` | 某站点/客户端按端口聚合的流量 |
| `GET /api/v1/flows?limit=100` | 明细流（协议/站点地址/端口/双向字节） |
| `GET /api/v1/status` | 原有端点，peer 新增 `rx_bps`/`tx_bps` |

均为原有 Bearer 令牌鉴权，只应在内网可达。

## 性能

- 每个转发包多一次 map 查表（key 是定长结构体，无字符串分配）+ 两次原子加；
  目标是 100 Mbps 混合流量下服务端 CPU 增幅 ≤ 2%。
- 控制 API 侧有 1 秒快照缓存：开多少个浏览器标签页都只采样一次。

## 升级

- **需要升级**：中转服务端（`server`）与 Web 控制面（`web`）镜像/二进制。
- **不需要升级**：站点 agent、客户端、密钥文件格式与隧道协议**均未变化**。
- 只升一半也能用：新 Web + 老 server → 端口表为空并提示读不到；老 Web + 新 server → 一切照旧。
