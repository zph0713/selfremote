# v0.4.0 — 站点接入改成「一行安装命令」+ 初次部署自带本机站点 + 路由模式开关

这一版把 v0.3 的「网页下载部署包 → 手工搬到目标机器」换成了**在目标机器上跑一行命令**，
并且**初次部署就把 server 自己的站点装好**——起完 compose 就是一个完整可用的服务。

## 新增

### 🚀 一行命令接入远程站点

在网页「站点 Agent」创建站点后，页面直接给出一条命令：

```sh
curl -fsSL http://<控制面>:8080/install.sh | sudo bash -s -- --code XXXX-XXXX
```

- 脚本从**控制面自己**下载 agent 二进制（不依赖 GitHub，离线环境也能装）
- agent **现场生成自己的密钥对**，用一次性**安装码**换注册（隧道地址、服务端公钥、网段映射）
  —— 私钥从不离开目标机器，控制面只见公钥
- 自动装成 systemd 服务（或 `--docker` 用容器方式），开机自启
- 安装码：8 位、有效期 60 分钟、**用过即失效**，随时可在页面「生成新安装码」换机/重置
- 站点与 server 之间的长期凭据就是那把密钥（Noise IK 双向认证）：**不再需要动态码**，
  agent 也就不用为了自动应答维护 TOTP —— 接入门槛降到「装机那一次」

### 🏠 初次部署自带本机站点

`init.sh` 现在会把「server 自己所在内网」这个站点一起准备好（密钥 + 配置 + 预置登记），
`docker compose up -d` 起来后：server / web / agent-home / db / nginx 全部就绪，
本机站点**已经在线**，不需要任何网页操作。管理员注册完成的一刻它就挂到你名下。

### 🧭 路由模式（网段冲突策略，网页可切换）

「站点 Agent」页新增开关，决定站点网段怎么呈现给客户端：

| 模式 | 行为 |
|---|---|
| **自动**（默认） | 不冲突就**直接用站点真实网段**；两个站点撞车时，后来者自动分到虚拟网段（`10.201.x`），站点侧做无状态地址翻译 |
| **真实网段** | 永远原样呈现；冲突的站点会被拒绝创建（自己改网段） |
| **总是虚拟** | 每个站点都映射到 `10.201.x`，客户端完全看不到真实网段 |

建站时也仍然可以手写 `192.168.1.0/24 => 10.200.7.0/24` 强制指定。

### 🔧 其它

- `sr agent enroll --server <url> --code <码> -o <config>`：装机脚本背后的接入命令，可单独使用
- 容器方式首启时若给了 `SR_ENROLL_CODE`/`SR_ENROLL_SERVER`，agent 会自己完成接入
- `sr pubkey -c <配置>`：打印配置里私钥对应的公钥（脚本用）
- agent 在 Linux 上自己配置 `ip_forward` + SNAT/转发规则（容器与裸机行为一致）
- 离线部署包（zip）保留为「目标机器完全没有网络」时的备选

## 升级（v0.3 → v0.4）

1. 拉新镜像（`selfremote` + `selfremote-web`），`deploy/stack` 里更新 `init.sh` / `.env.example` / compose
2. `.env` 里删掉 `SR_AGENT_KEYPASS`，确认 `LAN_CIDRS` 是本机内网网段
3. `bash init.sh`（幂等：已有的 `server.json` 跳过，补出本机站点的密钥与预置登记）
4. `docker compose up -d`
5. 旧站点：控制面首次启动会**清空 v0.3 遗留的站点动态码密钥**（站点改用密钥对认证），
   旧站点需要在目标机器上重新跑一次安装命令（页面点「生成新安装码」拿新码）

## 兼容性

- `sr gateway`（v0.2 直连模式）、`sr client`、`.srkey` 客户端密钥格式**不变**
- 站点侧不再使用动态码（v0.3 的 `totp_secret` 保留字段但不再生成；已有站点首次启动会被清空）
- 离线部署包（zip）与手工 `agent.json` 配置继续可用
