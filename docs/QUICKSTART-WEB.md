# Web 控制面：部署与使用（推荐方式）

> 一套 `docker compose` 起五件套：**nginx（反代）+ web（控制面）+ mariadb + server（中转服务端）
> + agent-home（本机站点）**。在网页上注册账号、绑定 Google Authenticator、管理站点与客户端密钥；
> 客户端连接需要 **文件密码 + 实时动态码**，站点接入需要它自己配置里的动态码密钥（自动应答）。

```
浏览器 ──▶ nginx :8080 ──▶ web ──▶ mariadb（账号 / 站点 / 设备）
                             │ 写 clients.json + agents.json（热加载）
                             │ 读管控 API（站点状态 / 启停 / 踢线）
                             ▼
                   server（中转服务端，host 网络；用户态转发，无 TUN 无特权）
                             ▲                          ▲
      Mac: sr client ────────┘                          └──────── sr agent（各站点，可位于 NAT 后）
     （文件密码 → 动态码）                                        （tun + SNAT + 地址翻译）──▶ 站点内网
```

## 0. 前置条件

- 一台能跑 Docker 的主机（群晖 NAS / Linux VPS / 树莓派均可）
- 客户端与站点能连到它：公网 IPv6（推荐）或公网 IPv4；UDP 端口默认 `28333`
- 站点机器（含本机站点）需要 `/dev/net/tun`；**中转服务端不需要**

## 1. 部署

```sh
# 拿到项目文件（任选其一）
git clone https://github.com/zph0713/selfremote && cd selfremote/deploy/stack
# 或者从 Releases 下载源码包后进入 deploy/stack

cp .env.example .env
vi .env                  # 至少改两个数据库密码 + SR_AGENT_KEYPASS；建议确认 LAN_CIDRS
bash init.sh             # 生成 server.json 与控制面令牌（幂等，只做一次）
docker compose up -d     # nginx + web + mariadb + server
```

浏览器打开 `http://<主机IP>:8080`（端口由 `.env` 的 `HTTP_PORT` 控制）。

> **不需要公网暴露 8080**：可以在家里局域网直接访问；出门后可以先把隧道连上，
> 再通过隧道里的内网 IP 访问本页面。管控 API（`API_PORT`，默认 8770）只应内网可达。

### 群晖 NAS 特别注意

1. 数据目录建议绝对路径：`.env` 里 `SR_CONFIG_DIR=/volume1/docker/selfremote`
2. IPv4 转发要宿主固定开启（一次性）：控制面板 → 任务计划 → 新增「触发的任务」→
   开机运行 `sysctl -w net.ipv4.ip_forward=1`（**站点**容器需要；中转服务端不需要）
3. 防火墙放行 `HTTP_PORT/tcp`（局域网访问可不放）与 `TUNNEL_PORT/udp`
4. 开启 Open vSwitch 的群晖无需再指定 LAN 接口（v0.3 的转发/NAT 规则不依赖接口名）

## 2. 首次使用

1. **注册管理员**：打开页面 → 「创建管理员账号」（仅第一个账号可自助注册，
   之后的新账号由管理员在「用户」页创建）
2. **绑定 Google Authenticator**：注册后自动进入绑定页 → 用 App 扫码 →
   输入 App 显示的 6 位码完成绑定 → **保存页面给出的 10 个恢复码**（手机丢失时用）
3. 之后登录 = 用户名 + 密码 + 动态码（或恢复码）

## 3. 添加站点（Agent）

> 本机站点（NAS 自己所在的内网）在 `docker compose up -d` 时**已经装好了**，无需操作；
> 下面说的是「再接入一台远程机器」。

「站点 Agent」→「＋ 添加站点」：

- **名称**：给自己看，如 `公司机房`
- **Agent ID**：小写字母/数字/短横线，如 `office`
- **站点内网网段**：每行一个，如 `192.168.1.0/24`（也可以留空，装机时用 `--routes` 指定）

创建后进入站点详情页，页面直接给出**一行安装命令**：

```sh
curl -fsSL http://<控制面>:8080/install.sh | sudo bash -s -- --code ABCD-EFGH
```

把这一行粘贴到**目标机器**（root）即可：它会下载 agent、用安装码换注册（密钥在那台机器上生成）、
装成开机自启的服务。目标机器只需要能出站访问控制面，**不需要任何入站端口**。

- **只有 docker 的机器**：命令末尾加 `--docker`
- **Linux 用 systemd**：默认路径；macOS 会提示手动/launchd 运行
- **网段冲突**：控制面路由模式是「自动」时，撞车的站点会自动分到虚拟网段（客户端见虚拟网段）；
  也可以在创建时手写 `192.168.1.0/24 => 10.200.7.0/24` 强制指定
- **安装码**：60 分钟有效、用一次即失效；换机器点「生成新安装码」
- **完全不联网的机器**：用详情页里的「离线部署包」（zip），拷过去按 README 运行

回到网页：状态应变成「在线」，并显示它上报的网段、版本与流量。

## 4. 生成客户端密钥

「客户端密钥」→「生成新客户端密钥」：

- **设备名称**：如 `mac-air`
- **可访问站点**：勾选这台设备能访问哪些站点（路由与服务端 ACL 同时生成）
- **密钥文件密码**：≥10 位；在客户端机器上运行时要输入它来解密文件。
  **服务器不保存私钥、也保存不了这个密码——忘记了只能重新生成**

点「生成并下载」→ 得到 `client-mac-air.srkey`（加密文件）。

> 也支持「导入已有公钥」：把以前配好的设备公钥登记进来继续用（同样要勾选站点）。
> 已有设备想增减站点：在设备列表里改（立即生效）；**若新增了站点，需要重新生成密钥文件**
> （旧文件里的路由不含新站点）。

## 5. 在 Mac 上连接

```sh
sudo ./selfremote-macos-arm64 client -c client-mac-air.srkey
# 该密钥文件已加密，请输入文件密码: ********
# 请输入 Google Authenticator 动态验证码（6 位）: 123456
```

看到 `════ selfremote 已连接 ════` 状态块即成功（内含服务端主机、隧道 IP、路由），
`Control + C` 退出并自动清理路由；服务端会立即看到你下线。

## 6. 日常操作与排障

| 动作 | 位置 |
|---|---|
| 看谁在线、流量多少 | 「总览」页（自动刷新） |
| 站点状态 / 启停 / 踢线重连 | 「站点 Agent」列表或站点详情页 |
| 站点换密钥 | 站点详情 → 重新下载部署包（会换新密钥，旧包随即失效） |
| 站点轮换动态码密钥 | 站点详情 → 轮换动态码密钥（需重新下载部署包并替换站点配置） |
| 吊销某台客户端 | 「客户端密钥」→ 吊销（在线会话数秒内被断开） |
| 加新账号 | 「用户」页（管理员）；新账号首次登录需自行绑定 MFA |
| 换手机 / 重装 App | 「设置」→ 重新绑定 |

常见问题：

- **动态码错误**：确认手机时间自动同步；连续错 3 次会锁定 30 秒
- **「暂时无法生成」**：服务端刚启动还没写 `netinfo.json`，等 30 秒刷新重试；
  或 `.env` 里显式设置 `SERVER_ADDR`
- **站点一直"离线"**：`docker logs <站点容器>` 看 agent 日志（应出现
  `═══ selfremote agent 已上线 ═══`）；确认站点能出站 UDP 到 `SERVER_ADDR`；
  确认网页上该站点是「启用」状态
- **站点上报网段与注册表不一致**：站点配置文件里的 routes 与网页里创建时填的不一致，
  重新下载部署包即可
- **改了 .env 里的数据库密码后 web 起不来（Access denied）**：MariaDB 只在**空数据卷**时
  初始化密码。要么 `docker compose down -v` 删卷重建（会清空账号数据），要么进 db 容器用
  root 改密码
- **客户端能连上但访问不到内网站点**：确认该客户端在网页上勾选了这个站点；
  确认站点的网段与你要访问的地址匹配（虚拟网段时按虚拟地址访问）
- **网页打不开**：`docker compose ps` 检查容器；`docker logs <项目名>-web-1`

## 7. 安全模型（简述）

- 客户端私钥只存在于你下载的 `.srkey` 文件里；站点私钥同理（文件密码加密：
  argon2id + ChaCha20-Poly1305）；服务端注册表只保存公钥
- 两条链路都要求动态码：客户端人工输码（防重放、失败锁定），站点用配置里的密钥自动应答；
  数据流量在通过校验前一律丢弃
- 中转服务端逐包校验来源（防伪造）与 ACL（客户端只能访问被勾选的站点），
  站点之间、客户端之间默认不可互访
- 登录密码 argon2id 哈希存储；会话 Cookie HttpOnly + SameSite；登录失败限速
- 数据（账号、站点、设备、会话）只保存在你自己的 mariadb 容器里
